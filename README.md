# Jamie-Node

自托管订阅门户：React 静态前端、Python 标准库后端、SQLite、3x-ui。
当前部署在 Noether，入口 https://sub.chuyi.uk/ 。

文档仅保留三份：[开发约束](AGENTS.md)、本页、[节点运维](NODE-OPERATIONS.md)。
历史改动和阶段验收查 Git，不作为当前操作手册。

## 代码入口

| 位置 | 职责 |
| --- | --- |
| `portal/`、`components/ui/`、`app/globals.css` | 前端；Vite 输出 `dist/portal` |
| `backend/server.py`、`application.py` | 启动、并发与应用组合 |
| `backend/http_api.py`、`http_types.py`、`routing.py` | HTTP 边界、请求类型、统一鉴权 |
| `backend/routes_*.py` | 认证、账号、订阅、支持、管理五组路由 |
| `backend/entitlements.py`、`package_ledger.py`、`cycles.py` | 兑换事务、账本、周期结算、同步 outbox |
| `backend/panel.py`、`node_catalog.py`、`node_sync.py` | 面板通信、动态节点目录、成员同步 |
| `backend/email_auth.py`、`ticket_notifications.py`、`subscription_notifications.py`、`account_deletion.py` | 邮箱认证、工单/套餐邮件、删除 |
| `backend/admin_users.py`、`operations.py`、`features.py` | 管理查询、运行诊断、自助功能 |
| `backend/payments.py`、`payment_gateway.py`、`routes_payments.py` | USDT 订单、网关查单、回调验签与事务发货 |
| `deploy/subscription_adapter.py` | 订阅格式及额度元数据适配，随版本部署 |
| `deploy/` | 部署、备份、探测、节点接入和验收工具 |

节点按运维流程登记，不修改节点数组/IP 常量。共享业务操作复用同一事务入口，不为每条路由复制实现。
新增节点运行 `npm run node:add`：向导自动检查系统、内存和端口，准备安装、注册并检查订阅同步。
NAT 节点可用 `--host IP --ssh-port 端口 --ports 分配范围 --name 名称 --region 地区`；
新 NAT 节点默认直接使用 VLESS REALITY TCP，自动校验兼容内核、实测后发布，无需手动迁移。
支持已有 SSH 别名或直接输入 IP/SSH 端口，参数可复用；详见 [节点运维](NODE-OPERATIONS.md)。
新账号在至少一个在役节点确认配置后即可导入订阅，其他节点继续重试；部分可用不代表同步完成。
停用、删除和凭据轮换仍保留完整确认流程，不因部分可用而提前完成。

离线节点仍保留在用户节点列表中并标注状态，只有目录中停用发布的节点才退出展示。
套餐计费模式的账号概览只读取本地账本，面板启用状态复用后台采样，超过 60 秒未更新显示未知，
避免面板故障拖慢首页；旧版非套餐计费模式仍沿用面板查询。同步等待页面每 15 秒刷新一次，
隐藏页面暂停刷新，后台请求不重叠；公开页面不等待账号接口，HTML 自带首屏加载提示。

## 业务约定

- 公开注册使用邮箱、密码、基础套餐卡密和邮件验证码；邮件未配置不能绕过邮箱注册。
  预览不消费卡密，最终注册事务才消费验证码、卡密并创建账号。
- 注册和兑换页支持用户主动点击读取剪贴板，权限拒绝时仍可手动粘贴。
  发卡后可复制兑换链接，卡密放在 URL fragment 中，打开后移除地址栏中的卡密、仅在当前页面内存中暂存。
  登录后填入兑换页，仍需预览套餐并确认，刷新后需重新打开链接；链接持有者可兑换，请私下交付。
- 基础套餐独立计额。提前续费时新套餐顺延：从现有有效、非永久基础套餐的最晚到期时间起计时，
  流量兑换后立即可用；永久卡不顺延，也不推迟其他套餐。
  流量包必须绑定有效基础套餐（流量耗尽仍可补充），不能用于注册；到期不晚于对应套餐/当前周期。
- 按最早到期顺序扣量，过期剩余作废。支持有限/无限有效期及不重置、月周期、指定天数周期。
  月周期以开通时间为锚点，按上海时区计算；月底按当月末处理但不漂移锚点，错过的周期不累积额度。
- 卡密兑换截止时间与套餐有效期不同；修改模板不追溯修改已发行卡密。
- 门户负责周期结算，面板累计计数不清零。面板执行额度与用户业务额度不是同一数值。
  零余额必须禁用，不能把面板的 `0`（无限额度）当作零流量下发。
- 无新鲜采样、计数回退等异常必须保留故障并核对账本，不能清空计数“修复”。
  计费和多节点同步是异步的，不能承诺高并发零超额或存量连接立即断开。
- 套餐计费已启用；有真实兑换后，不得直接关闭开关或回退到旧账本实现。
  卡密、套餐、审计及同步任务保持事务性，重试不能重复发放权益。

## USDT 支付

- 收款网关为 `https://pay.chuyi.uk`，使用商户 API Key 建单/查单；已有账号购买后自动到账，
  访客购买后通过领取凭证获得卡密，再走现有邮箱验证开通。付款不绕过注册验证。
- 套餐后台的 `USDT 在线售价` 为独立金额，留空或 0 关闭在线购买；不从人民币展示文案推算。
  金额按微 USDT 整数保存，订单保存创建时的套餐和价格，后续改价/下架不改变旧订单。
  本次运营定价为轻量月卡 1、标准月卡 3、长效季卡 5 USDT。
- 浏览器创建幂等请求凭证；访客凭证保存在当前标签页 sessionStorage，可复制含 fragment 的领取链接。
  关闭标签页/清理浏览器数据可能丢失凭证，请在付款前保存领取链接。凭证不能公开分享。
  网关只收到随机订单号、金额和通用返回地址，不接收网站账号、邮箱或领取凭证。
- `POST /api/payments/webhook` 是唯一使用原始 body HMAC-SHA256 认证、无需浏览器 Origin 的回调入口；
  验证 5 分钟时间窗、事件头、订单号和原价。回调只触发查单，不能直接发货。
  后台每 30 秒向网关认证查单，校验 USDT、订单、原价、实际金额、确认状态以及配置的收款网络/地址。
  网关可能为识别订单增加尾数，买家须支付收款页的准确金额，不能按套餐原价自行凑整。
- 生成内部卡、兑换权益、记账与完成订单在同一事务提交；重复回调、并发请求不重复发货。
  计费异常或账号停用时保留已付款状态并重试，不丢订单、不清零流量。未完成的支付订单会阻止账号删除。
  已完成订单在账号删除后匿名保留，过期单允许补查宽限期到账；退款需人工核对，不提供未经确认的自动退款。
- 生产私密配置 `/etc/jamie-portal.json` 的 `payments` 节：`enabled`、`api_key`、`webhook_secret`、
  `card_secret`、`wallets`（例如 `binance` 对应经商户确认的 BSC 地址）。缺少配置时不显示购买按钮。
  `card_secret` 用于稳定推导访客已购卡密，必须连同数据库私密备份，不能直接轮换或遗失。
  密钥不进入前端、Git 或日志。只开放商户实际配置并核实过的收款链。
- 后台「支付订单」可查看待付款、确认中、到账处理中、完成、过期及待核对订单；
  仅真实网关已完成状态可发货，测试使用模拟网关，不伪造生产到账或扣真实客户额度。

## 账号与数据边界

- 邮箱找回可用；换绑需身份验证及邮箱验证码，成功后撤销旧会话/恢复凭据。
  密码重置不能重新启用被停用账号。工单回复、流量不足和套餐到期邮件默认开启，保留已有的工单退订设置；用户可在账号页面分别关闭。
- 兑换、开通或后台赠送后发送到账通知（同一账号同批次合并为一封，含套餐、有效期、顺延开始时间、当前可用流量与服务截止）；
  属于交易通知，不受提醒开关影响，仅发送到已验证邮箱。首次启用时补发当天（北京时间）的兑换。
- 用户新建或回复工单时邮件提醒管理员（已绑定邮箱的管理员，否则发往配置的回复邮箱）；管理员已回复、
  有更新消息或工单关闭时不再发送。可在后台「工单」页关闭。后台「日志 → 邮件记录」可发送测试邮件。
- 工单回复、管理员提醒与到账通知约 30 秒内处理；流量与到期提醒每 5 分钟检查。
- 流量邮件在有效套餐合计剩余不超过 10% 时触发；到期邮件只在最后一份基础套餐到期前 3 天触发
  （续费顺延时不会对中间套餐误报）。未绑定邮箱的账号在首页提示绑定。
  仅发送至已验证邮箱；流量判断要求 120 秒内的有效账本采样。
  同一套餐组合/额度/重置周期或同一套餐到期时间只提醒一次；续费、补量后发送前重新校验。
  邮件队列持久化、失败退避重试（最多 5 次、23 小时内），换绑、注销或关闭提醒会取消待发邮件。
  使用现有邮件服务配置；服务商接受不等于送达。邮件不包含节点凭据或完整订阅链接。
- 管理后台为独立侧边栏工作台：概览、用户、卡密、工单、公告与套餐、日志；侧栏显示待回复工单与同步异常角标，可快速查找用户。
  管理员可在用户详情中直接「赠送套餐 / 加流量」：在同一事务内生成并兑换一张内部卡，复用兑换计费路径，
  记录在兑换历史（标记“后台赠送”）、发卡批次和操作记录中；停用或删除中的账号不能赠送。
  用户详情可写仅管理员可见的备注（最多 2000 字）；用户列表可按当前筛选导出 CSV（不含订阅链接或凭据）。
  发卡批次可一键作废其中未兑换且未过期的卡；操作记录可按类型、用户名或卡密尾号筛选分页。
  每张卡可记录仅管理员可见的「发给谁 / 备注」（发卡时批量填写，之后逐张修改，最多 100 字）；
  卡密查询以表格展示尾号、备注、状态、兑换账号与时间，边输入边搜索：完整卡密、兑换链接、尾号中连续 4–8 位、
  账号、备注或卡名均可；系统只保存卡密摘要与最后 8 位，卡密开头或中间部分无法搜索，页面会提示原因。
  侧边栏搜索框识别卡密 / 尾号 / 兑换链接时跳到卡密查询，其余按用户搜索。批次可点开查看每张卡去向。
  有多份基础套餐时，后台和用户首页同时显示最近到期与最晚到期（服务截止）。
  后台赠送的内部卡以 `cards.granted` 显式标记，不按时间推断。工单后台按待回复 / 已回复 / 已关闭筛选并可跳转用户详情。
- 用户端：置顶公告仅在未读时自动弹出一次，登录 / 开通 / 找回页面不弹，进入其他页面后再弹；
  在本浏览器登录过的访客默认进入登录而非开通页。打开兑换链接时，新访客进入开通页（卡密已填好），
  登录过的访客进入登录页，两者都提示已收到卡密并可切换。操作结果以浮动提示显示；未手动切换时跟随系统深浅色。
- 后台在手机上把表格显示为带字段名的卡片；用户筛选隐藏数量为 0 的分类。
- 管理后台「日志 → 邮件记录」可筛选状态、分页查看通知队列与新产生的验证码发送记录。
  发送元数据保留 90 天，包含收件人、主题、尝试次数、服务商编号和安全的失败摘要，不保存验证码或邮件正文。
  历史通知从已有队列展示，旧工单可能无原始收件地址；未接入回执，不推断送达或已读。
- “重置订阅链接”不撤销已下载的节点凭据；“重置连接凭据”是另一操作。
  两者均需重新导入，不能混淆安全承诺。
- 用户自删需密码和账号确认；管理员可确认删除普通账号，管理员账号受保护。
  删除先撤销网站访问，再重试清理面板身份，最后删除本地关联数据；失败保留任务供排查。
  已兑换卡不能重新使用。旧备份、已发送邮件及外部服务日志不会自动消失。
- 密码使用加盐 PBKDF2；会话保存摘要，Cookie 使用 Secure/HttpOnly/SameSite。
  写请求保留来源校验、JSON/自定义头、限流与服务端鉴权，SQL 参数化。
- 数据库包含节点凭据，属于私密数据。不得记录密码、卡密明文、Cookie 或完整订阅链接。
  访问目标日志未启用；网站会话、流量活动和代理在线状态不同，不宣称完全无日志。
- `private-admin.json` 仅为首次交付记录，改密后不代表当前密码。验收不得重置真实用户凭据。

## 开发与验证

手机端首页/套餐页提供可关闭的「添加到主屏幕」提示，关闭后七天不再主动提示，
「使用」和「我的」仍保留安装入口。支持安装事件的浏览器由用户点击后打开系统安装框；
iPhone 显示 Safari 分享菜单操作步骤，独立窗口运行时隐藏引导。
`public/manifest.webmanifest` 配置桌面图标和 standalone 启动；本版本不注册 Service Worker、
不离线缓存账户/API/支付数据，使用时仍需联网。未做 Web Push。
触屏设备减少卡片、导航和弹窗背景的实时模糊，保留原生滚动和时间驱动的 CSS 动效，
遵循减少动态效果偏好。刷新率由设备、浏览器和省电设置决定，不承诺固定 120Hz。

使用 Node >= 22.13、Python 3.11+、uv；已有依赖锁时使用 `npm ci`。

```sh
npm run dev
npm run check:python
npm run test:python
npm run check
node --test portal/navigation.test.mjs portal/features.test.mjs portal/dock.test.mjs
npm run build
```

也可运行 `npm run verify` 一次完成以上检查与构建。

Python 检查使用固定版本 Ruff 与 Pylint 重复代码检测，只在开发环境运行。
单测使用隔离数据库/模拟面板；`python3 deploy/benchmark_backend.py` 使用合成数据对比查询性能。
`/layout-review.html` 是本地界面样例，不进入生产构建，也不代表真实账号验收。
已移除旧 Next/Worker/D1 脚手架与未引用组件。前端仅通过 Vite 在本地构建，
线上由 Nginx 提供静态文件并反代 Python API，不运行 Vite 或 Node 服务。
后台编辑器、运营页面、工单和账号设置按需加载；同时发生的同路径 GET 共享请求，
不持久缓存账号响应，写操作前后清除共享请求，避免跨登录状态复用旧数据。
部署包只包含后端运行代码、前端产物及安装所需文件，不携带测试、Python 缓存或历史运维脚本；
成功安装后删除本次临时上传目录，备份与历史版本保留。安装有互斥锁，避免并发部署覆盖配置。

界面保留暖白/灰绿、紧凑卡片和无边框公告栏；公告不要在所有二级页面重复铺开。
底部导航挂到 body，认证/管理页面隐藏；未采用的 VisualViewport 实验不是线上行为。
图表不能把未采集日期伪造成零用量。保留 SVG 标识、官方客户端下载及简洁文案。
静态/SSR 测试不能替代 Safari 真机、客户端导入和交互验收。

## 运行配置

| 位置/服务 | 用途 |
| --- | --- |
| `/etc/jamie-portal.json` | 私密配置：数据库、站点、面板及邮件凭据 |
| `/etc/xui-clash.json` | 私密订阅上游配置 |
| `/etc/jamie-node-catalog.json` | 无凭据的运行时节点与服务元数据 |
| `/var/lib/jamie-portal/portal.db` | 私密业务数据库 |
| `/var/lib/jamie-portal/probe-identity.json` | 独立监测身份凭据，不复用客户身份 |
| `/var/lib/jamie-portal/connectivity.json` | 最近的数据面探测结果 |
| `/opt/jamie-portal/releases/`、`current` | 版本目录和当前代码链接 |
| `jamie-portal`、`xui-clash`、`x-ui` | 门户、订阅适配器和面板服务 |
| `jamie-portal-backup.timer`、`jamie-portal-probe.timer` | 本地备份校验和实际代理探测 |

Nginx 提供 HTTPS；门户仅监听 `127.0.0.1:18766`，适配器监听 `127.0.0.1:18765`。
`/assets/` 下的版本化静态资源启用 JS/CSS gzip 压缩及一年 immutable 缓存；
首页和 API 保持 `no-store`。部署脚本同时更新已有门户的 Nginx 配置。
Nginx 只信任 Cloudflare 官方出口的 `CF-Connecting-IP`，按真实访客地址限流；
直连来源不能通过伪造此请求头改变地址。官方网段维护于 `deploy/portal_runtime.py`。
部署保留最近 30 天的旧版本静态资源，避免已打开页面切换功能时加载旧脚本失败。
Resend 发信域名为 `notify.chuyi.uk`，密钥仅存私密配置。更换域名需同步 DNS/TLS、
Nginx、门户配置及目录元数据，不是改一个字段即可迁移。

## 部署与恢复

测试及构建通过后执行 `python3 deploy/deploy.py`，需要可用的 `Noether` SSH 别名。常规升级只需 SSH；
仅首次安装（服务器尚无 `/etc/jamie-portal.json`）需要私密面板环境文件，路径由 `JAMIE_XUI_ENV` 指定。不是通用新环境安装器。上传静态产物、后端和部署工具，无需服务器 Node。
部署保留已有配置/账号，备份并切换版本，同时安装订阅适配器。

```sh
python3 deploy/verify_clients.py
python3 deploy/verify_clients.py --metadata-only
ssh Noether systemctl start jamie-portal-probe.service
```

另需确认 `/api/health`、服务状态、同步错误及新静态产物。
客户端工具使用独立监测身份和隔离 Mihomo，不改系统代理；元数据验收不等于小火箭真机验收。
监测账号也有额度/期限，不能静默重置或冒用未确认归属的账号。

回滚前核对数据库与计费兼容性，协调门户和适配器版本；检查健康状态与 Nginx 配置后再恢复入口。
部署并非完整跨服务事务，尤其后续 Nginx 失败仍需人工核对。
备份会在隔离库校验完整性、外键与行数，不等于整机灾难恢复；不得拿生产库做恢复测试。
不要盲目恢复数据库覆盖新兑换、删除记录或账本。私密备份尚无自动清理策略。
旧一次性迁移/验收脚本不属于常规部署流程。
