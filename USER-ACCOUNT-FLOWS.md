# User account flows

- Package detail uses the ledger's expiry/created/id ordering. Add-ons identify their parent; all dates and balances come from the ledger, not frontend estimates.
- Email changes require current password plus old and new email codes. Legacy accounts without a verified mailbox require current password plus a new email code. Challenges are account- and credential-version-bound, single use, 10-minute expiry, five attempts. Commit rechecks account identity/status, changes login and verified email atomically, revokes sessions/recovery codes and cancels pending ticket mail. The requesting browser receives a new session. No real customer account was changed during verification.
- Link reset retains existing password confirmation. Link-only rotation does not revoke previously imported node credentials; the separate credentials action does.
- Ticket unread state is a per-owner message-id cursor. A GET does not mark read; the displayed message id is acknowledged by an ownership-checked POST. Staff views never mark customer messages read.
- Ticket email is opt-in, verified addresses only, no subject/body from customer tickets included. Reply creation and queue insertion share a transaction. The existing collector checks the queue approximately every five minutes, processes five items, skips read/disabled/opted-out recipients, retries five times with backoff within 24 hours, and uses Resend idempotency keys. Finished queue records expire after 30 days. Provider acceptance is not inbox delivery; no delivery webhook is claimed. Rate/volume monitoring is still an operator responsibility.
- Help contains accounting, support, data and email explanations. It does not claim a blanket no-logs policy.
- Adapter patch is separate from portal deployment: `python3 deploy/update_client_metadata.py`. It backs up the existing script, adds HEAD and portal/support headers, and leaves node conversion and credentials unchanged. Verify with `python3 deploy/verify_clients.py --metadata-only` using the existing dedicated probe, without exposing subscription tokens or changing the system proxy. Client-specific visual display still depends on client support; no iOS device test is implied.
